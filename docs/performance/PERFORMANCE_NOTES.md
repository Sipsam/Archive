# 로직 효율 개선 기록

## 측정 조건

- 기준 데이터: `data/lol_assignment_dataset/battle_logs.csv` 10,420행
- Python 3.12 / Windows 11
- 각 항목 1회 wall-clock 측정
- 외부 API 호출 없음
- 개선 전: `PERFORMANCE_BASELINE.md`
- 개선 후: `PERFORMANCE_AFTER.md`

## 적용 내용

1. 그룹별 Python 함수로 반복하던 승리 수·승률 계산을 사전 벡터화 후 `groupby sum/count`로 변경했습니다.
2. 동일한 정확 이항검정 입력은 제한된 LRU 캐시에서 재사용합니다.
3. Streamlit CSV 캐시는 절대 경로, 수정시간(ns), 파일 크기를 키로 사용합니다.
4. 마스터 테이블 컬럼 정규화는 DataFrame별 한 번만 복사·정리합니다.

검정 기준, FDR 검정군, Wilson 계산과 결과 필드는 변경하지 않았습니다.

## 전후 비교

| 구간 | 개선 전(초) | 개선 후(초) | 변화 |
|---|---:|---:|---:|
| CSV 데이터 로딩 | 0.720293 | 0.719563 | -0.1% |
| 이상 후보 탐지 | 6.129911 | 0.721305 | **-88.2%** |
| Streamlit 초기 렌더링 | 1.675983 | 1.606499 | -4.1% |
| Streamlit 동일 세션 캐시 재렌더링 | 미측정 | 0.247908 | 신규 측정 |
| 전체 실행 | 8.685048 | 3.195862 | **-63.2%** |

단일 측정이므로 수십 밀리초 항목의 증감은 유의미한 개선으로 해석하지 않습니다. Streamlit 초기 렌더링에는 데이터 로딩이 포함되며, 캐시 재렌더링 시간은 전체 실행 비교값에서 제외했습니다.

## 결과 동일성

- 기존 `anomalies`, `candidate_score`, `anomaly_score` 필드를 유지합니다.
- 표본 수, 승리 수, 승률, 전체 승률, 승률 차이 테스트를 추가했습니다.
- 자동 테스트와 Streamlit AppTest를 통과해야 개선을 유지합니다.
